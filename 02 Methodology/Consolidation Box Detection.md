# Consolidation Box Detection

## Goal

Объективно, программируемо и строго по прошлым данным идентифицировать границы диапазона консолидации (Consolidation Box) для пилотного исследования на BTCUSDT Spot (Binance, 15 минут).

## Consolidation Box Specification (Pilot v0.1)

Кандидатный Consolidation Box строится по 32 завершённым 15-минутным свечам:
$$t-32, \dots, t-1$$
(что соответствует 8 часам). Проверяемая свеча $t$ не участвует в построении box или его квалифицирующих признаков.

Границы диапазона:
- $H = \max(\text{High}_{t-32 \dots t-1})$ (сопротивление);
- $L = \min(\text{Low}_{t-32 \dots t-1})$ (поддержка);
- $W = H - L$.

Окно квалифицируется как Consolidation Box только при одновременном выполнении трёх условий:

### A. Относительно узкий диапазон
Процентная ширина диапазона:
$$w = \frac{H - L}{\text{Close}[t-1]}$$
Значение $w$ не превышает 20-й процентиль ширины завершённых 32-свечных окон за предыдущие 60 календарных дней. Процентиль вычисляется исключительно по окнам, полностью завершившимся до текущего кандидатного окна (будущие данные не используются). Долларовая ширина BTC на разных ценовых уровнях не сравнивается.

### B. Низкая направленность (Efficiency Ratio)
Для тех же 32 закрытий:
$$ER = \frac{|\text{Close}[t-1] - \text{Close}[t-32]|}{\sum_{i=t-31}^{t-1} |\text{Close}[i] - \text{Close}[i-1]|}$$
Требование:
$$ER < 0.30$$
Если знаменатель равен нулю, окно исключается как вырожденное. Низкий ER не доказывает идеальный баланс (например, разворот также может дать низкий ER).

### C. Расположение закрытий
Не менее 23 из 32 значений Close (минимум 70%) должны находиться в центральной области:
$$[L + 0.1W, H - 0.1W]$$
Если $W = 0$, окно исключается.

## Lifecycle of Box

1. Кандидат проверяется только по завершённым данным.
2. После квалификации границы $H$ и $L$ замораживаются.
3. Box становится активным со следующей 15-минутной свечи.
4. После активации $H$ и $L$ не пересчитываются.
5. Box действует максимум 32 следующие 15-минутные свечи (8 часов).
6. Учитывается только первый валидный breakout вверх или вниз.
7. После первого валидного breakout box немедленно закрывается.
8. Ложный breakout не удаляется из выборки.
9. Если breakout не произошёл за 32 свечи, box получает статус `expired`.
10. Пока один box активен, другой box не создаётся.
11. После breakout или expiration поиск нового box начинается со следующей свечи.
12. Одно событие может принадлежать только одному box.
13. Перекрывающиеся активные box не допускаются.
